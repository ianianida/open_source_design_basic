# 오픈소스기초설계 셸 프로그래밍 실습

우분투에서 실행하는 셸 스크립트 10개를 `src/`에 보관한다. 각 문제의 코드와 실제 실행 화면을 포함한 보고서는 `doc/`에 보관한다.

각 스크립트는 우분투에서 실행한 기존 화면을 바탕으로 검토했으며, 4.5 GPA 변경 및 검색 기능 확장에 따른 **새 실행 화면 촬영과 최종 DOCX 업로드가 남아 있다**. 보고서 캡처와 코드가 일치하도록 확인해야 한다.

## 실행 방법

저장소 최상위 폴더를 기준으로 실행한다.

```sh
sh src/ex3-0.sh
sh src/ex3-1.sh 12 5
sh src/ex3-2.sh
sh src/ex3-3.sh
sh src/ex3-4.sh
sh src/ex3-5.sh
sh src/ex3-5.sh -l src
sh src/ex3-6.sh files
sh src/ex3-7.sh links
sh src/ex3-8.sh Alice 2001-01-01
sh src/ex3-9.sh Alice
```

`ex3-0.sh`는 `~/.bashrc`에 `MYENV`를 등록한다. 기존에 다른 값의 `MYENV`가 설정되어 있으면 수정하지 않고 중단한다. `unset`은 해당 셸에만 적용되며 새 Bash를 실행하면 `.bashrc`의 등록값이 다시 적용된다.

`ex3-6.sh`와 `ex3-7.sh`는 지정한 폴더 안에 고유한 실습 폴더를 만들어 기존 파일을 덮어쓰지 않는다. `ex3-8.sh`와 `ex3-9.sh`는 현재 작업 디렉터리의 `DB.txt`를 함께 사용한다. `ex3-8.sh --new 이름 정보`는 기존 DB가 있으면 확인을 받은 뒤 새로 쓴다. `ex3-9.sh`는 이름 또는 정보의 일부를 입력해 검색할 수 있다.

예시 입력으로 열 문제를 차례로 확인하려면 `sh tools/demo.sh`를 실행한다. 특정 문제만 확인할 때는 예를 들어 `sh tools/demo.sh 4 5 6`처럼 번호를 지정한다. `EX3_PUBLIC=1 sh tools/demo.sh`는 공개용 화면에서 현재 사용자 이름을 가려 표시한다. 문제마다 30초씩 결과를 표시하며 테스트 파일은 임시 폴더에 생성한다. 이 자동화 실행은 기능 검증용이며, 4번과 5번의 메뉴 전체를 보여 주는 제출용 캡처를 대신하지 않는다. 다만 0번은 요구사항에 따라 사용자 `~/.bashrc`에 환경변수를 등록한다.

## 확인이 필요한 과제 조건

- PDF 4쪽과 5쪽의 두 요구사항이 모두 `ex3-5.sh`로 표기되어 있어 시스템 상태 메뉴와 함수의 `ls` 인자 전달을 하나의 파일에 포함했다. 교수님 확인이 필요한 해석이다.
- PDF에는 `ex3-4.sh`의 GPA 환산 기준이 명시되어 있지 않다. 이 구현은 평균 점수에 적용하는 **임시 예시 4.5 만점 기준**을 표시한다. 95점부터 A+(4.5), 90점부터 A0(4.0), 85점부터 B+(3.5)처럼 5점 간격을 사용한다. 교수님 기준이 확인되면 수정한다.

## 보고서 제출 상태

교수님 지시에 따라 `src/`는 소스코드, `doc/`는 DOCX 보고서 위치다. 보고서 작업본은 별도로 준비했지만 **GitHub `doc/`에 DOCX 바이너리 파일은 아직 업로드되지 않았다**. 보고서 속 4번(4.0 GPA) 및 9번(수정 전 검색) 캡처를 현재 소스코드의 실제 실행 결과로 교체한 뒤 `doc/`에 업로드한다. 자세한 내용은 [doc/README.md](doc/README.md)를 참고한다.
